## Why

The extension has `"TranslationFile"` enabled and a maintained `de-DE.xlf`, but 17 call sites across three objects pass plain string literals to `Error()`, `Message()`, `Confirm()`, and `Dialog.Open()` instead of a `Label` variable. Unlike object/field `Caption`/`ToolTip` properties, these literals are never extracted into `.g.xlf` — they cannot be translated at all, regardless of the user's language. A German user running the extension in English (or any future third language) would see these specific messages in English no matter what. Wrapping them in `Label` declarations, matching the convention already used elsewhere in the same files (`TXT001`, `ExportResultMsg`, `ResendAlreadySentQst`, etc.), closes that gap and makes the extension's user-facing text fully multilingual.

## What Changes

- Replace all 15 hardcoded string-literal calls in `Page 51001 "SL Sales Price Checking List"` with `Label` variables, consolidating duplicate text into a single shared `Label` per distinct message rather than one per call site:
  - `Error('Nothing to process')` (9 call sites across Validate/Approve/Add all Currencies/Upload Sales Price) → one shared `NothingToProcessErr` label.
  - `Message('validate data is done')` (1 call site) → `ValidateDoneMsg`.
  - `Confirm('Are you sure want to Accept New Price Setup?', false)` (1 call site) → `AcceptNewPriceSetupQst`.
  - `Message('done')` (2 call sites, Approve and Add all Currencies) → one shared `DoneMsg`.
  - `Error('not possible')` (1 call site, `OnModifyRecord`) → `ModifyNotAllowedErr`.
  - `ProgressWindow.Open('Validating Sales Price @1@@@@@@@@@@@@@@@')` (1 call site) → `ValidatingProgressMsg`.
- Replace the 1 hardcoded `Message('done')` in `Xmlport 51000 "SL Import Sales Price"` with a local `ImportDoneMsg` label.
- Replace the 1 hardcoded `Error('Please click Validate button.')` in `Table 51001 "SL Sales Price Checking"` with a local `PleaseValidateErr` label.
- **Explicitly excluded** (not UI text, must not become Labels): the two existing `StrSubstNo('...')` calls that build a JSON filename (`Codeunit 51000`) and an Isolated Storage key (`Table 51007`) — these are internal identifiers, not messages shown to a user, and translating them would be meaningless (the isolated-storage one would even change already-stored keys).
- After adding the labels, sync `Translations/SL Chronext Webshop.de-DE.xlf` with the regenerated `.g.xlf` and provide German translations for the 9 new trans-units.

## Capabilities

### New Capabilities
- `multilingual-messages`: All user-facing runtime messages, errors, confirmations, and progress text in this extension are declared as `Label`s (not string literals), so they are extractable and translatable via the standard BC translation file mechanism.

### Modified Capabilities
- None — this changes how existing messages are declared, not what they say or when they appear (message text stays character-for-character identical in English; German translations are new but don't change behavior).

## Impact

- `src/Pages/Pag51001.SLSalesPriceCheckingList.al`: 15 call sites updated, 6 new `Label` variables added.
- `src/Pages/XmlPort51000.SLImportSalesPrice.al`: 1 call site updated, 1 new `Label` variable added.
- `src/Tables/Tab51001.SLSalesPriceChecking.al`: 1 call site updated, 1 new `Label` variable added.
- `Translations/SL Chronext Webshop.g.xlf` (regenerated by compiler) and `Translations/SL Chronext Webshop.de-DE.xlf` (maintained): 9 new trans-units, all translated to German.
- No behavior change: the English text shown is byte-for-byte identical to today; only its source (literal vs. `Label`) and its translatability change.
